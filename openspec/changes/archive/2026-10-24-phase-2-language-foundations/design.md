## Context
F1 pasó62Node/27herramientas/46E2E. GG existente opera original hero/variables locales, no scheduler textual ni clon/audio. Pyodide314.0.7 requiere module worker y su loader tiene eval para enlazar EM_JS; QuickJS browserglue0.32.0 no presenta esos sitios JS.
## Goals / Non-Goals
Ejecutar fuentes libres reales QuickJS/Pyodide sobre secuencia, repetición, condiciones, variables locales, movimiento y espera, conservando documentos/autoría. No afirmar equivalencia de eventos/clones/audio aún, no convertir arbitrariamente texto a bloques ni ejecutar listadoIR F1.
## Decisions
### Documentos
GGPROJ1 sin textos mantiene esquema exacto y exportación1. GGPROJ2 tiene authoring {blockly,deviceSource,textDocuments,selectedTextDocumentId}; hasta8documentos con {id,name,language,source,runtime:{engine,version}}. ID text-UUID, nombre1–80sincontroles, language javascript/python, source <=65536bytesUTF8, IDs únicos, selección null o ID existente. Locks de documento exactamente quickjs0.32.0 / pyodide314.0.7 según lenguaje. Recursos/locks2D anteriores no cambian; límites totales/ZIP siguen aplicando y prevalecen sobre límites por campo. Un array vacío en v2 conserva v2; una carga v1 no migra hasta crear documentos explícitos. No guardar código compilado ni runtime mutable.
Parse/import/restore valida todo antes de reemplazar; docs son autoría independiente y conservan IDs/fuentes mediante ZIP/autosave. El almacenamiento existente sigue transaccional actual/anterior. Fuente incompleta o con error sintáctico se puede guardar como texto; el diagnóstico ocurre al ejecutar, sin borrar autoría.
### Runtimes y fronteras
Paquetes propios fijados: quickjs-emscripten-core0.32.0, @jitl/quickjs-wasmfile-release-sync0.32.0 y pyodide314.0.7, assets estáticos locales con hashes. Parser propio acorn8.19.0. No consumir QuickJS transitivo PXT ni CDN/instalación automática de imports. El binding QTS_Eval0.32.0 usa una variable módulo no inicializada con compileOnly; por ello no se usa esa ruta. El parser admite módulos ECMAScript2022/top-level await y rechaza importaciones; el motor recibe la misma fuente tras la activación, sin envoltorios de texto.
Nuevo origen textual (4176 en E2E,4186 manual) y iframe sandbox allow-scripts allow-same-origin; worker module efímero por Run. Shell y runner2D conservan sus CSP. Solo rol textual permite WASM y evaluación JS de glue Pyodide; excepción documentada y probada, nunca evaluación del alumno en shell/2D. Permissions-Policy sin capacidades privilegiadas, conexiones self, sin credenciales académicas.
Preflight en worker carga runtime y compila sin ejecutar (JS módulo ECMAScript2022 validado por Acorn8.19.0 sin evaluar; Python compile con top-level await). Runtime ausente/sintaxis inválida conserva escena/sesión activa. Tras preparación válida se reemplaza runner, prepara escena inicial IR con variables locales de autoría, vincula scope vigente y ejecuta. Stop y otra acción Run/import anulan candidatos y workers anteriores; un candidato preparado solo sobrevive al reset interno que lo activa.
### API inicial y mensajes
GG textual experimental ofrece scene.get, sprite.get/move/setPosition, variables.get/set y events.emit con semántica existente, más wait(seconds0..60) del worker. Estos bindings no se anuncian como SDK estable. console.log/print producen registros acotados. No resolver módulos o paquetes remotos ni exponer DOM/VM/almacenamiento del shell.
RPC enumerado valida origen/source en handshake, versión, sesión textual, sesión/revisión del runner, documento, secuencia, requestId, aridad/tipos y tamaño antes de reenviar. Máximo64solicitudes pendientes y16KiB por RPC; mensajes/logs1024 unidades UTF-16 (como consola F1; hasta4KiB UTF-8),100registros por ejecución más aviso de límite; se prioriza un error terminal adicional y la consola conserva únicamente los100registros más recientes. Resultados DTO desprendidos; ningún objeto host se entrega al intérprete.
QuickJS usa contexto propio, memoria32MiB/pila512KiB, interrupción por turno de300ms y jobs/promesas explícitos. Python permanece en worker terminable; límite temporal de ejecución120s y fuente64KiB, sin prometer límite fino de heap Python que el loader no ofrece. Stop invalida primero, plazo cooperativo150ms y destrucción worker/frame; shell debe responder incluso con bucle infinito.
Diagnósticos amplían origen javascript/python y sourceLocation {documentId,line,column?} opcional con enterospositivos acotados/ID vigente. Solo se enlazan líneas existentes del documento correspondiente; nunca IDs Blockly inventados. Editar invalida enlaces anteriores. Registros/código derivado no pasan a GGPROJ; fuentes textuales sí son autoría.
### Interfaz
Crear documento JavaScript/Python y elegirlo explícitamente; editar no cambia Blockly. Ejecutar documento usa backend elegido; Ejecutar bloques conserva ruta anterior. Dispositivo micro:bit mantiene su fuente propia. Enlace de diagnóstico selecciona documento/línea y enfoca textarea. Stop y estado aria-live locales junto al botón Ejecutar documento. Controles/errores/Stop accesibles en móvil; recuperación inicial bloquea edición hasta restaurar documentos.
## Risks / Trade-offs
Permiso dinámico del nuevo origen textual requiere comprobar SOP/CSP/puente; no es un sandbox completo por quitar globals. Pyodide inicia más lento/grande que QuickJS; cargar bajo demanda. Copia textual de corpus completo y capacidades de eventos/clones/ámbitos/disfraces/audio quedan pendientes del próximo corte F2; no fingir equivalencia con APIs inexistentes.
